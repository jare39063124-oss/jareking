## 1. 背景与目标

### 1.1 我们在解决什么问题

| 痛点 | 现状 | jareking 的答案 |
|---|---|---|
| WPS 会员墙 | PDF 编辑、格式转换、AI 功能等核心能力被锁在付费会员后 | 基础编辑功能**永久免费**，付费点仅限 AI 额度与少量高级功能 |
| 订阅制疲劳 | WPS/Adobe 年费绑定，停订即失能 | **不搞订阅制**：安装送积分，充值得积分，支持一次性买断 |
| AI 绑定厂商 | 办公软件的 AI 功能绑定自家模型，不可更换 | AI 服务商**用户自配**（任意 BaseURL + Key），平台不强制捆绑 |
| 迁移成本 | 换软件意味着重学操作习惯 | 界面布局、快捷键、操作逻辑对标 WPS/Office，**零成本迁移** |

### 1.2 灵感来源：Compositor 现象

前 Apple/Google 设计师 Robbie Tilton 因 Photoshop 太贵、GIMP 不顺手，自建了免费开源的 Compositor——PS 老用户零学习成本迁移，靠"体验丝滑"赢得用户。

**jareking 复制这个逻辑到办公套件赛道**：不做功能数量的军备竞赛，做"WPS 用户丝滑迁移 + AI 代差体验"。

### 1.3 产品定位

> **jareking = WPS 的平替甚至更优解**：完整兼容 Word/Excel/PPT/PDF 的办公套件（Windows 桌面端），内置用户可自配 API 的强大 AI 助手，通过"积分 + 买断"商业化，不搞订阅制。

### 1.4 v1 目标（成功标准）

1. WPS 用户下载 jareking 后，能直接打开/编辑/保存 .docx/.xlsx/.pptx 文件，常用格式无明显丢失
2. 用户配自己的 API Key 即可用全部 AI 能力；平台托管额度待服务器就绪后开放
3. 商业化闭环跑通：安装送积分 → 用 AI → 第三方平台充值/买断 → 门控生效，全链路可走通
4. Windows 10/11 可安装、可自动更新

### 1.5 现实边界（重要）

WPS 是 30 年积累、千人团队的产品。jareking 采用 **"保真分级 + 分阶段交付 + 子 Agent 并行开发"** 策略：

- 格式兼容分三级保真（L1 文本结构 / L2 常规格式 / L3 高级特性），v1 目标 **L2**，L3 降级提示
- 功能按 Phase 交付（见第 9 章），每个 Phase 有独立验收标准
- 专用开发机 24 小时不间断运行，积极调度子 Agent 并行推进各模块

### 1.6 品牌名可用性检索结论（2026-10-12）

| 检查项 | 结果 |
|---|---|
| jareking.com | ❌ **已被占用**（尼日利亚艺术家在线画廊，活跃站点，非软件类） |
| jareking.cn / .com.cn / .io / .app | ✅ 无 DNS 记录，可注册（.net 未确认，建议同步检查） |
| npm 包名 jareking | ✅ 可用 |
| PyPI 项目名 jareking | ✅ 可用（JSON API 404） |
| GitHub 用户名 jareking | ❌ **已被占用**（无关用户，Node-RED 贡献者，2026 年仍活跃） |
| 商标（初步检索） | ⚠️ 未发现完全一致的 "jareking" 注册商标；**近似风险**：第9类已注册"捷雷克"（含"可下载应用软件"类目，2025-06 注册）；另有沉寂老牌 "GENEKING/竞开"（点击科技协同软件，2002-2005） |

**结论与行动**：

4. 正式商标检索（商标网 sbj.cnipa.gov.cn 或阿里云商标服务）后，以**个体工商户名义**申请第 9 类（可下载软件）+ 第 42 类（软件即服务）；不建议注册"捷雷克"音译中文名（已被人注册）
5. 海外市场暂不布局，无需处理 .com/.io 等国际域名

## 3. 目标用户与典型场景

### 3.1 目标用户

- **被会员墙劝退的个人用户/学生**：想要"免费够用"的办公套件
- **成本敏感的中小企业**：不愿承担 WPS 商业版授权费用
- **AI 重度办公人群**：希望用自然语言直接处理文档，而非手动操作

### 3.2 典型场景

1. **无缝迁移**：WPS 用户双击 .docx 直接用 jareking 打开，编辑保存，格式不回丢，快捷键一样
2. **AI 改文档**：选中一段文字 → "改成正式语气并精简到 100 字" → 预览 diff → 一键应用
3. **AI 处理表格**：对 .xlsx 说"按月份汇总销售额并生成柱状图" → 自动写公式 + 插图表
4. **免费用户**：安装送本地积分，配自己的 API Key 免费用全部 AI；平台托管额度待服务器就绪后开放
5. **买断用户**：一次性付费永久解锁全部高级功能，无订阅焦虑

## 4. 功能需求

优先级：**P0** = v1 必须 · **P1** = v1.5 · **P2** = v2

### 4.1 应用框架（P0）

- 启动页、最近文件、多文档标签页
- 菜单栏 + Ribbon 式功能区（布局对标 WPS，降低迁移成本）
- 命令面板（Ctrl+Shift+P）
- 文件关联：.docx/.xlsx/.pptx/.pdf 双击用 jareking 打开
- 深浅主题、界面缩放、多语言（中文优先）
- 自动更新、异常崩溃恢复（未保存文档恢复）

### 4.2 Writer 文档模块（P0 核心）

- 打开/保存 .docx（保真 L1/L2，见 7.3）
- 富文本编辑：字体/段落/样式/列表/表格/图片/超链接/分隔符
- 页面设置：页边距、纸张、方向、页眉页脚、页码
- 目录自动生成、批注、查找替换、拼写检查
- 快捷键体系对标 Word/WPS
- 导出 PDF

### 4.3 Sheet 表格模块（P0 核心）

- 打开/保存 .xlsx
- 单元格编辑、数字/字体/边框/填充格式化、合并单元格、行列增删隐藏
- 公式引擎（v1 常用 200+ 函数，逐步扩展至 500+）
- 排序、筛选、条件格式、冻结窗格
- 基础图表：柱状/折线/饼图/散点
- 导出 CSV / PDF

### 4.4 Presentation 演示模块（P0，v1.1 修订：不接受降级）

- 打开/保存 .pptx（基础保真）
- 幻灯片编辑：文本框、形状、图片、表格、主题母版
- 基础动画与切换、放映模式
- 导出 PDF
- AI 一键生成（大纲 → 成稿）

### 4.5 PDF 模块（P0 阅读 / P1 编辑）

- **阅读（P0）**：PDF.js 渲染、缩放翻页、文本选择、目录书签、全文搜索
- **编辑（P1，高级功能/积分门控）**：页面增删/合并/拆分/旋转/提取、注释、基础文本与图片编辑
- **创建**：从 Writer/Sheet/Presentation 导出 PDF

### 4.6 AI 助手（P0 核心差异化）

- **入口**：右侧边栏对话 + 文档内选中浮动工具条 + 命令面板
- **API 配置**：多服务商配置管理（任意 BaseURL + Key + 模型名）、连通性测试、密钥本地加密存储
- **自然语言编辑文档（Writer）**：格式指令（"第三章字号改小"）、内容指令（"全文公司名加粗"）、润色/续写/翻译/摘要
- **自然语言处理表格（Sheet）**：公式生成、数据汇总、图表生成、数据洞察（"哪个月销售额最低"）
- **内容生成（Presentation）**：大纲 → 成稿、一键生成 PPT
- **上下文引用**：AI 可读取当前文档/选中区域作为上下文
- **双模式计费**：自带 Key 模式不扣积分；平台托管模式消耗积分（服务器就绪后开放，v1 先落自带 Key）

### 4.7 账号与云同步（v1.1 修订）

- **本地账户（P0）**：设备本地账户，绑定积分余额与许可证；支持账户文件导出/导入（换机迁移）；无需注册登录、无需联网
- **云同步（预留，P2）**：注册登录（邮箱/手机 + 微信/Google/Apple）、云盘、多端同步、版本历史——**v1 不实施**，仅预留数据模型与接口

### 4.8 商业化模块（P0，落地路径见 6.5）

- 新用户安装送本地积分（建议 1000 分，数值待定）
- **积分充值**：v1 经第三方创作平台外链完成（爱发电/面包多等），兑换码发放积分
- **一次性买断**：离线签名许可证，永久解锁全部高级功能
- **高级功能门控**：PDF 编辑、批量格式转换、去水印导出等
- **激励视频广告**：v1 暂缓接入（见 6.2），仅预留积分入口抽象

## 5. 非功能需求

| 类别 | 指标 |
|---|---|
| 性能 | 冷启动 < 3s；100 页文档打开 < 2s；编辑输入延迟 < 50ms；大表（1万行）滚动流畅 |
| 兼容 | Windows 10/11（x64）单平台；无需考虑 macOS/ARM 适配 |

| 隐私 | 用户 API Key 与文档内容不用于任何训练；明示隐私政策；纯本地运行默认无数据外传 |
| 稳定 | 崩溃率 < 0.1%；自动更新失败可回滚版本 |

## 6. 商业模式设计

### 6.1 积分经济（需求方已确认可行）

| 项目 | 设计 |
|---|---|
| 新用户赠送 | 安装送 1000 积分（本地发放） |
| 充值档位 | ¥6=1000 / ¥30=6000 / ¥68=15000（含赠送） |
| 买断版 | ¥199 一次性：永久解锁全部高级功能 + 每月赠 5000 积分（本地发放，服务器就绪后改为服务端发放） |
| AI 消耗 | 按 token 估算：约 1 积分 ≈ 1K tokens；结构化操作类技能按次扣费（10~50 积分/次） |
| 免费功能 | 所有编辑、查看、导出基础格式**永久免费**，不消耗积分 |

### 6.2 广告（v1 暂缓，架构预留）

桌面端 Windows 应用没有面向个人开发者开放的合规广告 SDK（穿山甲/优量汇等均要求企业主体且以移动端为主）。**v1 不接入广告**，但积分系统保留"看广告得积分"的来源抽象层，待企业资质就绪后启用。

### 6.3 买断激活

- 离线许可证：ed25519 私钥签名激活码，客户端本地验签，无需服务器
- 激活码 + 本地账户绑定 + 设备数限制（如 3 台）
- 支持转移授权（旧设备解绑 → 新设备激活）

### 6.4 付费墙边界（明确清单）

| 免费 | 积分/买断 |
|---|---|
| 全部编辑功能（Writer/Sheet/PPT） | AI 助手（平台托管额度；自带 Key 免费） |
| PDF 阅读、Office 导出 PDF | PDF 编辑、批量转换 |
| 基础格式导入导出 | 去水印导出、模板中心高级模板 |

### 6.5 个人开发者约束下的商业化落地路径

**当前约束**：个人独立开发者、无企业主体、无微信/支付宝商户号、无云服务器。

**v1.0（当前约束下）**：
- **充值入口**：应用内"充值/购买"按钮跳转第三方创作平台（爱发电 / 面包多等，个人可入驻，平台抽成 + 支付通道费以各平台公示为准），用户完成支付后获得兑换码，应用内兑换积分或激活买断许可证
- **发放方式**：v1 支持人工发码（个人可承受的单量）+ 平台自动发货（半自动）
- **积分与账户**：全部本地存储（SQLite），换机靠账户文件导出/导入
- **许可证**：本地 ed25519 验签，私钥妥善保管（私钥泄露 = 许可证体系被伪造，需制定私钥备份与轮换预案）
- **广告**：不接入；**平台托管 AI 额度**：不开放（无服务器计量），主推自带 Key

**v1.5+（资质与基础设施就绪后演进）**：
1. 注册**个体工商户**（成本低、可申请微信支付商户号，费率约 0.4%）→ 应用内原生支付，同时解决商标申请主体问题
2. 购入廉价 VPS + 域名 → 服务器端积分流水、账号系统、平台托管额度计量、云同步
3. 企业资质就绪后评估广告联盟与更大事态

## 7. 技术选型（推荐方案）

### 7.1 桌面框架：Electron + TypeScript

**理由**：
- 文档处理生态（docx/xlsx/pptx/pdf 库）几乎全部优先支持 JS/TS
- 24h 不间断 Agent 并行开发模式下，TS 生态的 AI 可编码性最高（训练数据最丰富）
- 原生能力（菜单、托盘、文件关联、自动更新）全部有成熟方案
- 单平台（Windows）进一步降低构建与测试成本

### 7.2 前端：React 18 + TypeScript + Tailwind CSS + Zustand

- 组件库：Radix UI（无样式基元，便于对标 WPS 视觉）
- 构建：electron-vite + pnpm workspace（monorepo：`apps/desktop`、`packages/core`、`packages/ai`、`packages/server`（预留））

### 7.3 文档引擎

| 模块 | 方案 | 说明 |
|---|---|---|
| Writer | 自研文档模型 + TipTap（ProseMirror）编辑器内核 | docx 解析：JSZip + OOXML 流式解析 → 文档模型；导出：文档模型 → OOXML 序列化。保真分级：L1 文本与结构 / L2 常规格式 / L3 高级特性（v1 目标 L2） |
| Sheet | Univer（开源电子表格框架）+ SheetJS 文件层 | 公式引擎：v1 集成 formula.js 起步，核心函数自研替换 |
| Presentation | 自研幻灯片编辑器（Konva/Fabric canvas）+ 自研 pptx 解析 + PptxGenJS 生成 | v1 全量范围 |
| PDF | PDF.js（阅读渲染）+ pdf-lib（编辑/生成） | 成熟方案，直接集成 |

### 7.4 后端服务（v1 仅本地，服务端预留）

- v1 **零服务端依赖**：账户、积分、许可证全部本地
- `packages/server` 保留 NestJS + PostgreSQL + Redis + MinIO 的脚手架结构（暂不部署），供 v1.5+ 启用
- 预留接口：积分流水上报、账户绑定、云同步协议

### 7.5 AI 层架构（核心创新）

**适配器模式**，统一协议抽象：

```
用户配置 (BaseURL + Key + Model)
        ↓
   AIAdapter 接口
   ├── OpenAICompatibleAdapter（覆盖 OpenAI/DeepSeek/通义/Kimi/智谱等）
   ├── ClaudeAdapter
   ├── GeminiAdapter
   └── OllamaAdapter（本地）
        ↓
   Skill 层（文档操作技能）
        ↓
   LLM-as-Planner → 结构化操作指令（JSON ops）→ 本地 Executor 确定性执行
```

**为什么用 Planner/Executor 而不是让 LLM 直接改文档**：
- 可靠性：LLM 输出结构化指令，本地代码确定性应用，不产生幻觉改动
- 可回放：每次 AI 操作都是一条 ops 记录，可预览 diff、可撤销、可审计
- 积分计量：按 ops 精确计费

操作协议示例：

```json
{
  "plan": [
    { "op": "format.apply", "target": "selection", "style": { "bold": true } },
    { "op": "text.replace", "find": "旧公司名", "replace": "新公司名", "scope": "document" }
  ],
  "explanation": "已将选段加粗，并全文替换公司名",
  "estimatedPoints": 30
}
```

### 7.6 支付

- v1：第三方创作平台外链（爱发电/面包多）+ 兑换码体系，无支付资质门槛
- v1.5+：个体工商户 → 微信支付/支付宝原生支付（Windows 端）；不再涉及 Apple IAP

## 8. 系统架构

```
┌─────────────────────────────────────────────────────┐
│  Electron 主进程（Windows）                          │
│  ├── 窗口/菜单/文件关联/自动更新                        │
│  ├── 本地文档库（SQLite + 文件系统）                    │
│  ├── 本地账户与积分（SQLite，设备绑定）                  │
│  ├── 许可证验签（ed25519，私钥在构建机）                 │
│  └── IPC 总线                                         │
├─────────────────────────────────────────────────────┤
│  渲染进程（React）                                    │
│  ├── 应用框架（标签页/Ribbon/命令面板）                 │
│  ├── Writer 引擎（TipTap + 文档模型 + docx 解析/导出） │
│  ├── Sheet 引擎（Univer + 公式引擎）                   │
│  ├── Presentation 引擎（canvas）                      │
│  ├── PDF 引擎（PDF.js + pdf-lib）                     │
│  ├── AI 面板（对话 + 配置 + ops 预览）                 │
│  └── 商业化 UI（积分/充值外链/兑换/激活/门控）           │
├─────────────────────────────────────────────────────┤
│  AI 层（主进程 Node 侧）                              │
│  ├── Adapter（OpenAI兼容/Claude/Gemini/Ollama）       │
│  ├── Skill（Writer/Sheet/PPT 技能集）                 │
│  └── Planner → Executor（ops 协议）                   │
├─────────────────────────────────────────────────────┤
│  云端服务（v1 不部署，接口预留）                        │
│  ├── 积分流水/账户同步                                 │
│  ├── 云存储与同步                                      │
│  └── 原生支付（个体工商户后启用）                        │
└─────────────────────────────────────────────────────┘
```

数据流（AI 改文档）：用户指令 → Skill 组装 prompt（含文档上下文）→ Adapter 调用模型 → Planner 输出 ops → Executor 本地应用 → diff 预览 → 用户确认 → 扣本地积分 → 写入文档模型 → 持久化。

## 10. 风险与开放问题

### 10.1 主要风险

| 风险 | 影响 | 缓解策略 |
|---|---|---|
| .docx/.pptx 全保真 round-trip 是行业级难题（ONLYOFFICE 做了十年） | 复杂格式文档打开后格式漂移 | 保真分级 + 打开时提示 + "另存为 jareking 格式"保留编辑态 |
| Electron 体积与内存占用 | 轻量用户流失 | 按需加载模块；单平台部署降低构建复杂度 |
| 第三方平台充值体验中断（依赖外部平台） | 转化率低、平台政策变动 | v1 可接受；v1.5 个体工商户后迁移原生支付 |
| 许可证私钥安全 | 私钥泄露 → 激活码被伪造 | 私钥离线保管 + 备份 + 泄露时轮换（吊销旧签名的版本号清单随更新下发） |
| 广告无法接入（个人无资质） | 免费用户无广告收入 | 主推充值+买断；广告入口预留待资质就绪 |
| 无服务器 → 积分/账户仅本地 | 重装系统丢积分、多设备不同步 | 账户文件导出/导入 + 明确提示；v1.5 上云解决 |
| 商标音译近似风险（捷雷克，第9类） | 华语市场品牌纠纷 | 正式检索确认；必要时换用图形商标或调整中文名 |
| 子 Agent 并行开发的集成一致性 | 模块接口漂移 | 接口契约先行（先定 TypeScript interface 再并行） |

### 10.2 待需求方确认的开放问题

1. 积分面额/充值档位/买断定价是否按 6.1 执行？（"可行"已确认，数值仍可调）
2. 第三方充值平台选哪家：爱发电 / 面包多 / 其他？
3. GitHub 组织变体名定 **jareking-app** 还是 **jareking-office**？
4. 个体工商户注册的时间计划（影响原生支付与商标申请节奏）？
