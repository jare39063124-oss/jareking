## 1. 项目是什么

**jareking**：WPS 平替办公套件（文字 / 表格 / 演示 / PDF），核心理念来自 Compositor 取代 Photoshop 的现象——**让 WPS 用户零成本丝滑迁移**，差异化是 **AI 比 WPS 强**（自然语言直接操作文档）。

- **平台历史**：spec v1.1 曾决定「**Windows 单平台，放弃 macOS**」（`docs/spec.md`）。**本次交接意味着该决策被推翻**——macOS 重启、新增 Android。**新对话必须先改 spec 的平台章节**，否则文档与实现不一致。
- **v1 硬约束**：**零服务端**（本地 SQLite 账户/积分、无云）；`packages/server` 仅为脚手架。
- **商业模式（后置）**：安装送本地积分 → 第三方平台（爱发电/面包多）充值 → 一次性买断；积分消耗于 AI + 高级功能。个人开发者、无企业资质。
- **体积战略**：见 `docs/size-strategy.md`。Electron 安装包 111MB / 解包 376MB（已瘦身 42%）。**用户对体积高度敏感**（对标 Compositor 12MB），任何平台方案都要把体积写进评估。

## 6. 踩坑清单（血泪，别重蹈）

**Electron / 构建**
1. `ELECTRON_RUN_AS_NODE=1` 被沙箱注入 → 起 GUI 必须 `env -u ELECTRON_RUN_AS_NODE`。
2. 构建必须带 `CODEBUDDY_SAFE_DELETE_ENABLED=0`，否则安全删除策略拦截 electron-builder。
3. **Electron 44 移除 `File.path`** → 取文件路径必须 `webUtils.getPathForFile`（已封装进 preload）。
4. `electron-updater` 是 **CJS**，ESM 主进程必须默认导入再解构，具名导入运行期失败。
5. `printToPDF.pageSize` 单位是**英寸**（传微米 100% 失败：`Failed to generate PDF`）；Electron 44 的 `landscape` 对该路径无效 → 用 `preferCSSPageSize` + `@page size`。
6. `window.prompt/alert` 会**阻断 CDP 自动化**（历史踩坑：公式/超链接/编辑文字都因此改 Modal）。
7. push 走 token `insteadOf`；当前环境**代理不通、直连可用**（`env -u http_proxy ... git push`）。

**Univer（表格）**
8. 固定 unit id `jareking-sheet` 重复创建会抛 `cannot create a unit with the same unit id` → 必须先 `disposeUnit`。
9. sheet 配置键**必须用默认 id**（`sheet-01…`），自造键名与权限点注册错位 → 写入被静默拦截（弹「范围已保护」）。
10. 创建后需逐表 `getWorksheetPermission().unprotect()` 解除默认创建者保护。
11. locale 必须 `LocaleType.ZH_CN`（`'zhCN'`），`'zh-CN'` 会崩。
12. **1.0.4 无 `insertImage`/浮动图片 API** → 图表只能「生成 PNG + 预览/下载」。
13. 样式回写：`JkCellStyle ↔ IStyleData` 双向映射在 `univerAdapter.ts`（#47 曾断裂，已根治）。

**pdfjs / pdf-lib**
14. pdfjs 4.7：`page.render({ canvasContext, viewport, transform })`（**v5 才改名 `canvas`**）；文本层用 **`TextLayer` 类**（非 `renderTextLayer`），容器须设 `--scale-factor = viewport.scale`。
15. pdf-lib 内建 Helvetica 无法编码 CJK（`WinAnsi cannot encode "机"`）→ 中文水印走 **canvas→PNG 位图**（`addImageWatermark`，零依赖零字体打包）。

**OOXML / 解析**
16. **exceljs 对「非 xlsx」不报错、回落空簿** → 必须校验包内 `xl/workbook.xml`（否则伪造空表 → 用户误判文件为空 → 覆盖保存 → **数据丢失**）。
17. **pptx 导出必须有母版/版式/主题骨架**（`slideMaster1.xml` + `slideLayout1.xml` + `theme1.xml` + `sldMasterIdLst` + 各 rels），否则 WPS/PowerPoint **打不开**（曾只导出 5 个部件，挂起 45s+）。
18. pptx 里 schema 非法的 `p:notesSldIdLst` 已移除（`CT_Presentation` 无此元素）。
19. fflate：条目 API 是 **`file.start()`**（不是 `next()`），且必须先 `register(UnzipInflate/UnzipPassThrough)`。
20. 分节段落 round-trip 会净增空段（已修：空的分节段落只产 SectionBreak）。
21. `printToPDF` 走 CSS 流式分页，**不是** WPS 精确分页引擎。

**TipTap / 状态**
22. TipTap 保持 **v2.27**（v3 破坏性迁移）；`setColor`/`setFormat` 无选区时需 `pendingMarks` 暂存，且 color 挂 `textStyle` 而非独立 mark。
23. `StrictMode` 下 effect 双调用会误触发（排练计时曾因此「一进就结算」——不要用 effect 卸载兜底做结算）。
24. `setState` updater 内不要做副作用。

### 7.1 结论先行
Electron **原生支持 macOS**，这是「改造成本最低」的路径。核心工作不是重写，而是：
① 打包配置；② **Windows 专有能力的平台替代**；③ 签名/公证；④ 平台耦合点抽象。

### 7.2 必做清单

| # | 事项 | 具体动作 |
|---|---|---|
| 1 | **打包 target** | `apps/desktop/electron-builder.yml` 目前**只有 `win` + `nsis`**。需加 `mac: { target: [dmg, zip], arch: [x64, arm64] }`（注意 Apple Silicon 需 arm64）。 |
| 2 | **平台专有功能替代** | ⚠️ **Office 转 PDF 用 Windows PowerShell + COM（`shared/officePdfScript.ts` + `main/services/officeConvert.ts`）→ macOS 不可用**。替代方案：LibreOffice headless（`soffice --convert-to pdf`，需检测安装）/ AppleScript 驱动 Office for Mac / 或 macOS 上直接隐藏该入口（用「导出 PDF」打印管线替代）。**必须抽成平台适配层**（如 `platform/pdfConvert.{win,mac}.ts`）。 |
| 3 | **路径与文件系统** | APFS 默认**大小写不敏感**（`Foo.docx` 与 `foo.docx` 同文件）→ 文件名比较/去重逻辑需复核；`doc:reveal` 用 `shell.showItemInFolder`（跨平台可用）；`userData` 路径变为 `~/Library/Application Support/jareking`。 |
| 4 | **文件关联** | `electron-builder.yml` 的 `fileAssociations`（docx/xlsx/pptx/pdf）在 mac 需生成 `CFBundleDocumentTypes`，electron-builder 支持，但**需实测双击打开 + 单实例计数**（主进程 `open-file` 事件，Windows 走 `argv`，**代码路径不同**）。 |
| 5 | **签名 / 公证** | 需 Apple Developer（$99/年）。未签名的 .app 会被 Gatekeeper 拦截。正式分发需 `hardened runtime` + `entitlements` + `notarytool` 公证；本地开发可先 `identity: null` 跳过签名。**electron-updater 在 mac 必须签名后才可用**。 |
| 6 | **菜单栏** | macOS 有全局菜单栏（`Menu.setApplicationMenu`），Windows 用的窗口菜单/快捷键（Ctrl → Cmd）需适配；Ribbon 里的 `Ctrl+1`（单元格格式）、`Ctrl+F/H`（查找替换）、`Ctrl+F1`（折叠功能区）要按平台映射 `metaKey`。 |
| 7 | **体积预期** | Electron macOS 解包通常 300–400MB（与 Windows 同量级）。若用户坚持小体积，需评估 **Tauri**（Rust + 系统 WKWebView），但那是另一次迁移。 |
| 8 | **spec 更新** | `docs/spec.md` 的平台章节写明「放弃 macOS」→ **必须改为「Windows + macOS 双平台」**，否则后续模型会按旧决策行事。 |

### 7.3 风险
- macOS 上**无 WPS/Office COM** → 「Office↔PDF」这一卖点需替代实现或降级（用户可能不接受"功能缺失"）。
- 公证流程需 Apple 账号与网络（当前环境网络不稳）。
- 打印管线 `printToPDF` 在 mac 可用（三模块导出 PDF 可复用），但**字体依赖本机字体**，mac 与 Windows 字体集不同 → 需视觉验收。

## 8. Android 版专项（新对话 A）

### 8.1 结论先行（最重要的一段）
**Electron 不能运行在 Android/iOS**（Electron 只支持 Windows/macOS/Linux）。所以 Android 版**不是"打包一下"，而是换外壳**。

好消息：**业务核心（docx/xlsx/pptx/pdf 的模型 + 解析 + 导出）是纯 TypeScript，可以高度复用**；编辑器层是 Web 技术（React + DOM canvas），理论上也能在 WebView 里跑。

### 8.2 三条路线（建议 A）

| 路线 | 做法 | 体积 | 改动量 | 评价 |
|---|---|---|---|---|
| **A. Capacitor + WebView**（推荐） | 用系统 WebView 承载现有 React 渲染层；Electron API 换成 Capacitor 插件 | **APK 约 10–20MB**（不打包 Chromium） | 中（IPC 层 + 文件系统 + 触屏 UI） | **最快见效，且体积小**（契合用户的 Compositor 情结） |
| B. Tauri v2 Mobile | Rust 核心 + 系统 WebView | 约 5–10MB | 中高（需 Rust + 插件重写） | 体积最优，但团队需 Rust 能力 |
| C. React Native 重写 | 原生 RN 组件 | 中 | **极大**（Univer/Konva/TipTap 全需重写） | ❌ 不推荐 |

### 8.3 包复用矩阵

| 包 | 可复用性 | 说明 |
|---|---|---|
| `packages/writer` | ✅ **直接复用** | jszip + fast-xml-parser，纯 JS，无 Node 依赖 |
| `packages/presentation` | ✅ **直接复用** | jszip + fflate，纯 JS |
| `packages/pdf` | ✅ 复用（部分） | pdf-lib 纯 JS；pdfjs 需 canvas/worker（WebView 可用，需确认 Android WebView 版本） |
| `packages/sheet` | ⚠️ **需处理** | exceljs 依赖 Node `stream`/`Buffer`（有 browser build 但体积大、移动端性能差）；建议评估换 **SheetJS(xlsx)** 或加 Buffer polyfill |
| `packages/core` | ⚠️ **需替换底层** | 契约/逻辑可复用；`sql.js`（WASM）+ Node `fs` 在 Android 需换 **Capacitor SQLite** + `Filesystem` 插件 |
| `packages/ai` | ✅ 复用 | 纯 fetch/SSE（后置，见 §9） |
| `apps/desktop/src/renderer` | ⚠️ 大部分复用 | React 19 + Tailwind + TipTap + Univer + Konva 在 WebView 可跑，但**触摸交互/软键盘 IME/性能需实测**；Ribbon 需改触屏布局 |
| `apps/desktop/src/main` | ❌ 重写 | Electron 主进程（窗口/菜单/29 个 IPC/文件对话框/自动更新）→ 换 Capacitor 插件桥 |
| `apps/desktop/src/preload` | ❌ 重写 | `contextBridge` → Capacitor 插件 API（可保留 `window.jareking.invoke` 形状，底层换实现，**改动最小化**） |

### 8.4 必做清单

| # | 事项 | 说明 |
|---|---|---|
| 1 | **外壳选型 spike** | 先用 Capacitor 建空壳，验证：Android WebView 版本、Univer 加载、pdfjs worker、Konva 触摸绘制。**先出报告再动代码**。 |
| 2 | **IPC 适配层** | 保留 `window.jareking.invoke(channel, payload)` 签名不变，底层改为 Capacitor 插件分发（29 个通道逐一映射：`doc:read-file` → Filesystem、`db:query` → SQLite、`system:openExternal` → App/Browser 插件…）。 |
| 3 | **文件读写** | Android 必须走 **SAF（Storage Access Framework）** 或 Capacitor Filesystem；不能假设任意路径可读写。`<input type=file>` 在 Android WebView 可用但受限。 |
| 4 | **数据库** | `sql.js` → `@capacitor-community/sqlite`（或 expo-sqlite 若换 RN）。迁移脚本（`migrations.ts` 现有 v1→v3）可复用，**SQL 方言需复核**。 |
| 5 | **移除/替代桌面专有能力** | Office 转 PDF（PowerShell COM）→ **Android 不可用**（可用「导出 PDF 打印管线」，但 Android 无 `printToPDF`，需改 canvas 渲染 PDF 或用 Android Print Framework）；宏 Worker（Web Worker 在 WebView 可用）；自动更新（改 Play Store / 应用内检查）。 |
| 6 | **触屏 UI 重做** | Ribbon（功能区）在手机屏不可用 → 改 底部 TabBar + 抽屉/底部弹层；工具栏按「最近使用 + 更多」渐进披露；表格/演示的缩放手势、长按菜单、双击编辑要重做交互。 |
| 7 | **软键盘与 IME** | TipTap/ProseMirror 在 Android WebView 的软键盘遮挡、选区跳变是老问题 → **必须真机实测**，可能需要 `visualViewport` 适配。 |
| 8 | **性能基线** | 移动端内存/CPU 远低于桌面：`WRITER_CHUNK_SIZE=300`、100MB 大文件策略需重新评估（手机可能只支持 10–20MB 流畅）。 |
| 9 | **体积** | Capacitor APK（含 WebView 内容，不含 Chromium）目标 **20–30MB**；若换成 Tauri 可更小。**必须把体积写进验收**（用户敏感）。 |

### 8.5 风险
- **Univer 在移动端的表现是最大未知数**（表格是核心卖点，若卡顿则方案 A 需重估）。
- Android 碎片化（WebView 版本、厂商 ROM）→ 需最低 API 与 WebView 版本矩阵。
- 「Office 互转」与「打印」两项在 Android 上能力缺失，需产品决策（隐藏/降级/云端转换——但云是后置的）。
